## 2026-09-03 — упрощение таблицы и новый визуальный стиль

- В колонке токена оставлено только название со ссылкой на заранее заполненную торговую пару Matcha; иконка, адрес контракта и технический статус убраны.
- В колонке даты оставлена только дата без подписи о количестве покупок.
- `Ср. покупка` заменена на `MCap покупки`, `Ср. продажа` — на `MCap продажи`.
- Обе исторические капитализации выводятся в USD. Формула: `средняя цена сделки в ETH × ETH/USD на дату сделки × supply`.
- Для нескольких покупок используется средневзвешенный курс ETH/USD по фактически затраченному ETH. Для продажи BOWYER используется курс даты продажи.
- Исторический ETH/USD зафиксирован по дневным свечам Binance ETHUSDT; это расчётная капитализация, а не архивный снимок агрегатора.
- В качестве supply сначала используется величина, согласованная с текущими `MCap / price` Blockscout; при её отсутствии — `total_supply` токена.
- Из-за периодических ограничений Blockscout supply дополнительно читается напрямую из ERC-20 `totalSupply()` и `decimals()` через публичный RPC Robinhood Chain; контрольная проверка вернула supply для всех 25 позиций.
- Контрольные расчёты: FRONG — MCap покупки около `$3M`; GTR — около `$1,25M`; BOWYER — MCap покупки около `$151,28K`, MCap частичной продажи около `$911,05K`.
- Интерфейс переработан в контрастный чёрный дашборд: сетчатый фон, отдельная секция обзора, акцентная зелёная рамка, более плотная таблица и самостоятельный блок методики.

## 2026-09-03 — расширение покрытия MCap и стабилизация котировок

- Причина пропусков MCap установлена: Blockscout не публикует `circulating_market_cap` и `exchange_rate` для значительной части новых токенов, хотя торговые пары уже существуют.
- Основным источником текущего MCap и справочной USD-цены выбран публичный API DexScreener `token-pairs/v1/robinhood/{contract}`.
- Для защиты от ложных или нерепрезентативных пулов сначала выбирается самая ликвидная пара, где котировочным активом является ETH, WETH или USDG. Только при отсутствии такой пары разрешается самая ликвидная нестандартная пара, и источник явно помечается как менее надёжный.
- Локальная контрольная проверка заполнила MCap для 24 из 25 позиций. CLIPPY определяется примерно как `$2,42M`, JINQIAN — примерно как `$0,53M`; значения меняются вместе с рынком.
- Для DISHWASHER у DexScreener не найдено индексируемой пары. В GitHub Actions добавлен резервный расчёт MCap по малой 0x-котировке и onchain `totalSupply`; если исполнимого маршрута нет, вместо выдуманного значения остаётся прочерк.
- Для полной оценки позиции основной 0x-маршрут дополнительно сравнивается со справочной spot-оценкой. При аномально слабом ответе проверяются firm quote AllowanceHolder и Permit2 price, после чего используется лучший исполнимый результат.
- Индикативный 0x-запрос синхронизирован с режимом Matcha без подключённого кошелька: `taker` не передаётся, поскольку он необязателен для `/price`. Для firm quote адрес кошелька и `sellEntireBalance=true` сохраняются, поскольку там моделируется исполнение всего фактического остатка.
- GitHub Actions теперь сохраняет последние успешные 0x-котировки в отдельном Actions Cache и восстанавливает их на следующем запуске. Срок жизни котировки в интерфейсе ограничен двумя часами; это убирает случайные прочерки при единичном сбое API, не превращая старые данные в «текущие».
- Отображение чисел унифицировано: не более двух знаков после запятой. Ненулевые ETH-значения меньше `0,01` показываются как `<0,01`, а не округляются до ложного нуля.
- В методике сайта и подвале указан DexScreener; тёмный дизайн и структура дашборда сохранены без изменений.
